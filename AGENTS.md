# Production rules for 120-second narrative motion video

These rules are mandatory whenever the task involves the video project. Act as a director, professional motion designer, animator, editor, and QA reviewer, not as a code generator that exports the first functioning render.

1. AUDIT BEFORE REWRITE: inspect the current repository, rendering toolchain, storyboard, voice generator, captions, source assets and previous MP4. Preserve usable code. Do not assume Remotion, Manim, Blender or MoviePy is currently used.
2. NARRATION FIRST: establish the complete *verified* Russian/Ukrainian voiceover text (never fabricate a transcript). Map every spoken assertion to on-screen visual evidence. Script -> timed beat sheet -> storyboard -> animatic -> final render. Narration and visuals must be synchronised, not two independent streams.
3. EXPLAIN, DON'T DECORATE: in every shot one visually explicit idea, clear subject, causal relationship, readable focal point. Do not generate random glowing lines, floating coins, anonymous stick figures or inconsistent symbols to fill space.
4. PHYSICS AND GEOMETRY: store consistent coordinates, layer order, perspective, object dimensions and character rig per shot. Enforce physical contact of feet and props, light emanating from a source and hitting a surface, believable acceleration and object trajectories, appropriate occlusion and scale. Stylisation is allowed; unintentional contradictions are not.
5. DESIGN SYSTEM: one cohesive illustration style and character library, at most 2 fonts and a disciplined accent palette. Avoid primitive stick-figure placeholders as finals. 16:9, 1920x1080, 30fps unless user requests other. Typography must be legible at phone size; respect safe margins.
6. EDITORIAL TIMING: target 120 seconds +/- 5 seconds, normally 14-20 meaningful shots/visual states; adapt to narration rather than fill fixed quotas. No stagnant 20-second composition unless its on-screen information evolves meaningfully. Prefer distinct visual changes at thought boundaries, without frenetic random cuts.
7. VOICE: record or synthesize 3 short, normalized A/B/C voice tests from the SAME text before replacing the voice. Offer a professional, natural documentary-style narrator; consistent accent, neutral warmth, no exaggerated radio-announcer voice. Pronunciation and phrasing are manually checked. No imitation of a real person's voice without authorization.
8. SOUND: voice is primary. Measure LUFS/true peak with FFmpeg; aim approximately -16 LUFS integrated for the finished narrated video, peak <= -1.5 dBTP (platform-specific targets may differ). Music/FX must not mask words. A sample-rate conversion is not an improvement in original recording quality.
9. CHECK BEFORE FINAL: render a fast animatic/low-res preview first, generate actual frame contact sheets, inspect the transition frames, render full MP4 only after checking frames. Check low-resolution/mobile preview, audio clipping, length, black frames, captions, and mismatches with voice. A computer cannot fully verify physics from metadata: conduct visual judgement of rendered frames and fix failures.
10. HONEST REPORTING: report what you inspected, what was fixed, remaining limitations, file paths, commands, and actual render duration. Never claim a tool, MCP server, API voice or QA pass if unavailable or not executed. Ask for API keys via environment/secure secret storage, never write secrets into repository or skill files.

When the user requests a new/edited scene, invoke the `narrative-video-director`, `visual-physics-audit`, and `voice-director` project skills as relevant.
